What blocks a fully live demo from Bhilai today

  • Bhilai has no hub on the real backend. A farm's location is the phone's GPS fix and a lot is accepted only within 60 km of a hub. From Bhilai the farmer can sign in and register a farm, but listing a lot is refused, and a Bhilai address is not serviceable. Hubs for Bhilai are the first item in section 9.
  • Hub intake has no screen. It is one command (scripts/hub_intake.py) until it has one.
  • The app has not been rehearsed on a phone against staging. The recording ran the same app and the same backend code on the development server. Rehearse way B before the day.

B. The live walk, about six minutes

Start the app from the mobile folder and scan the QR code with Expo Go:

$env:EXPO_PUBLIC_API_URL = "https://staging.farm2home.galabavamsi.com"; npx.cmd expo start --clear
WhoDoSay
1Hub, laptopOpen the hub desk (the site's front page) and /ops.html; sign in. "This is one hub: what is on its shelves, what is held for carts, and a live feed of everything that happens."
2Customer, phoneSign in as Customer. Choose Bangalore, MG Road. "No password: a code by email. The address decides the hub, and the shop shows only what that hub can deliver now."
3Customer, phoneAdd two of an item. View cart. Hold my items. "Holding sets the units aside for ten minutes: whole cart or nothing." Point at Held going from 0 to 2 on the hub desk.
4Customer, phoneType an address. Pay."Payment is a stand-in; no money moves. The order now waits for a picker."
5Picker, laptop or a second phoneOpen /picker.html?store=1. Get next order. Scan all. Mark packed. "The picker is sent to the bin holding the oldest batch. Every unit is scanned. Only at packing does stock on hand go down."
6Customer, phoneOpen Orders, then the order."Packed. From here it would be pooled with its neighbours into one trip. That is what we build next."

Before the day

  • Use mobile data. The campus and office networks tried so far block the site's new domain. Put the laptop on the phone's hotspot and check that https://staging.farm2home.galabavamsi.com/health answers.
  • Install Expo Go on the Android phone.
  • Fetch the staff password for the hub's pages from AWS Secrets Manager (farm2home/staging/staff-password). The built-in password is refused on a hosted site; the pages ask for the real one once.
  • Have an inbox open on the phone. The sign-in code arrives by email in a few seconds, is good for 10 minutes, and can be asked for once a minute.
  • Do not press "Reset demo data" on the hub desk on staging: it wipes everything back to the starting data.
  • Sign in to AWS only if you mean to deploy. The demo itself needs no AWS session.

The receiver's step, when a lot is expected

Staging's shelves hold the prototype's groceries today; produce appears once a farm lot is taken in. When a lot is on its way to a hub, the receiver's step is one command, and the packs are on sale as it prints each line:

$env:STAFF_PASSWORD = "the staff password"
py scripts\hub_intake.py --url https://staging.farm2home.galabavamsi.com --store 1 --received 39.5 --rejected 1.5 --grade A

C. The app on demo data

From the mobile folder, with no address set:

npx.cmd expo start --clear

Any email signs in and the code is 123456. Nothing leaves the phone. Choose Bhilai, Supela. Show a rescue deal, a product's grade and harvest date, checkout, and the order moving to Out for delivery with its door-step code. Sign in as Farmer to list a lot in Bhilai. Say plainly that this is demo data: these are the screens, not yet the system.
